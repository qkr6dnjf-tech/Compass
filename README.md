# 입찰 나침반

전북·전주·군산·익산의 조경식재·조경시설물 공사를 위한 개인용 모의투찰 서비스입니다.

## 현재 사용 범위

웹 화면, 예측 API, 공유 전처리, ANN·부스팅 학습/실행, 모델 버전 저장, 사용자별 D1 기록, 변경 이력, 개찰 결과 비교를 구현했습니다.

**나라장터 공개 화면에서 실제 자료를 수집하고 ANN·부스팅 모델을 학습해 연결했습니다.** 수집 건수·지역별 분포·제외 사유는 자료 관리에서, 실제 학습 건수와 검증 성적은 모델 학습에서 확인합니다. 개찰 전 공고는 결과를 만들지 않고 대기 상태로 표시합니다.

공식 원문으로 확인한 전주 공고 R26BK01491586-000을 공고·금액 산식 검산용으로 제공합니다. 공개 화면에서 예비가격 15개·선정 4개·업체 115개의 결과를 확보하고 평균 예정가격 및 추첨 횟수를 검산했습니다. 공식 결과 공개시각은 확인되지 않아 원본에는 최초 관측시각을 보존합니다. 사용자가 전체 흐름 검증을 우선하도록 요청해, 연구용 학습에서는 실제 개찰 후 7일을 이용가능 시점으로 가정합니다. 실제 수집시각이 더 빠르면 그 확인시각을 사용합니다. 이 가정은 실제 공개시각을 입증하지 않으며 모델·성적·예측 기록에 표시합니다. 현장 소재지가 아니라 실제 입찰참가 지역제한을 지역으로 분류합니다.

## 사용 순서

1. 수집한 실제 자료와 학습 모델이 기본 제공됩니다. 자료 관리에서 공고별 예비가격·업체내역·제외 사유를 확인하고 JSON으로 내려받을 수 있습니다. 추가 자료는 정규 JSON으로 등록합니다.
2. 모델 학습에서 최근 30·60·200건 또는 직접 입력(20~400건)을 선택합니다. 선택한 수는 실제 가중치 학습에 쓰는 공고 수이며 모델 선택 10건·최종 검증 10건·특징 계산용 선행자료는 별도입니다. 자료가 부족하면 학습을 실행하지 않습니다.
3. 모의투찰에서 개찰 전 기록 또는 과거 연습을 선택하고, 참가제한 지역·공고·가격순 번호를 고릅니다.
4. API가 반환한 두 후보를 비교하고 하나를 저장합니다.
5. 이미 결과가 있는 과거 공고는 저장 즉시 비교됩니다. 개찰 전 기록은 결과 대기 상태이며, 동일 공고번호·차수·분류·재입찰의 실제 결과를 등록하면 금액·순위·번호 포함 여부를 확인합니다.
6. 새 선택은 기존 기록을 보존한 새 이력입니다. 실전 성적에는 해당 공고의 마감 전 마지막 유효 기록만 포함합니다. 과거 연습과 실전 성적은 분리합니다.

사이트는 링크로 누구나 접속하며 ChatGPT 로그인 없이 공고 조회·학습·예측·저장을 사용할 수 있습니다. 기록은 D1 서버에 저장하고 HttpOnly 쿠키의 임의 식별정보로 브라우저별로 구분합니다. 쿠키의 원문은 저장 기록에 포함하지 않습니다. 쿠키를 삭제하거나 다른 기기로 접속하면 이전 비로그인 기록에 접근할 수 없으므로 자료 관리에서 백업을 내려받으세요. 이미 로그인한 사용자는 기존 계정의 기록을 그대로 사용하며, 비로그인 방문자에게 계정 기록을 공개하지 않습니다.

## 번호·사정률·금액

- 사정률 = 예정가격 / 기초금액 × 100. 100% 부근의 비율이며 ±0% 편차 형식이 아닙니다.
- 원본 추첨번호를 보존하고 가격 내림차순 1~15로 별도 정렬합니다. 가격이 같은 경우 원본번호 오름차순으로 정렬합니다.
- 전체 조합 1,365개, 특정 번호를 포함하는 조합 364개입니다.
- 실제 15개 가격은 개찰 후 공개됩니다. 대상 공고의 개찰 후 가격을 예측에 사용하지 않습니다. 최근 6개월 이전 공개 공고의 비등간격 가격분포를 조건부 시나리오로 사용합니다. 표시된 조합 예시는 해당 이전 공고의 가격순 번호이며, 대상 공고의 실제 가격이 아닙니다.
- 두 후보는 0.200%p 이상 떨어져 있고 서로 다른 0.200%p 구간에 속합니다. 불가능하면 예측을 거절합니다.
- 다섯 자리는 조합 평균을 계산 후 반올림한 값입니다. 임의 난수나 세 자리 뒤의 00 덧붙이기가 아닙니다. 출력 정밀도와 정확도는 다릅니다.
- A값 보정식: (가정 예정가격 − A) × 하한율 + A. 금액단위로 절상합니다. 정수/BigInt 산술을 사용하며 실제 결과 비교는 반올림된 표시 사정률이 아닌 원 단위 실제 예정가격을 사용합니다.
- 순공사원가는 명시한 `ceil-each` 규칙(환산·98% 각각 원 단위 절상)만 지원합니다. 다른 규칙은 `unsupportedConditions`에 기록하고 가격순위를 보류합니다.
- 공고 가격조건 확인이 끝나지 않으면 금액 환산·저장을 보류합니다. 참여업체 전체가 확인되지 않으면 유효 모의순위를 부여하지 않습니다.
- 금액 1순위, 동가, 번호 포함, 최종 낙찰·계약 체결을 구분합니다.

## 학습·검증

`lib/domain.mjs`, `lib/model.mjs`를 Node 학습 프로그램과 배포된 Cloudflare Worker API가 공유합니다. 별도 Python 서버나 외부 모델 서버가 필요하지 않습니다.

학습은 가격조건 충족·양의 잔차·유효 업체 대비 단독 가격 1순위 결과를 라벨로 사용합니다. 후보 특징은 비율, 번호, 이전 관측분포, 조합 그룹빈도, 금액·지역·월 정보입니다. ANN은 은닉층 1개(8), 2개(32·16), 3개(32·16·8)를 선택할 수 있으며 기본값은 2층입니다. 입력은 13개, 출력은 후보 평가 점수 1개입니다. 모든 구성은 tanh 은닉층·sigmoid 출력·60 epoch로 학습합니다. 학습 파라미터 수는 각각 121·993·1,121개입니다. 2·3층은 Xavier 초기화와 전체 층 역전파를 사용합니다. 선택한 ANN과 로지스틱 부스팅(결정 그루터기)을 비교하고, 모델 선택 10건에서 더 높은 성적의 모델을 저장합니다. 동률이면 ANN입니다. 기존 1층 저장 모델의 가중치·추론도 계속 지원합니다. 동일 자료에서 모델 선택 10건과 최종 검증 10건을 고정하고, 그 이전의 최근 N건으로 학습합니다. 선택한 이용시점 기준이 다음 구간의 첫 예측시점을 넘는 표본은 제외합니다. 확인된 공개·수집시각만 쓰는 기준과 연구용 개찰 후 7일 기준은 분리합니다. 학습 건수별 모델을 따로 저장하며 예측할 모델 버전을 사용자가 고를 수 있습니다.

학습 종료일과 **모델 선택 종료일**이 모두 대상 예측시점보다 빨라야 합니다. 과거 연습의 이전 6개월 집계도 저장된 모델의 이용시점 기준을 공유하며, 대상 공고 자신의 결과는 입력에서 제외합니다. 최초 후보(A)를 미리 택하는 고정 규칙으로 성적을 계산하고 ‘둘 중 하나 성공’은 별도 지표로 공개합니다. 빈도·조건부 기준선과 ANN·부스팅을 비교하며 기준선보다 낮으면 그대로 표시합니다. 모델점수는 보정된 성공확률이 아닙니다.

기본 실제 모델은 data/public-models.json에 저장되어 서버에서 실행됩니다. 웹에서 추가 학습하면 해당 계정 또는 브라우저의 D1 기록에 새 버전으로 저장됩니다. 모델 성적 탭에서 가중치를 다운로드할 수 있습니다. 오프라인 실행:

```powershell
node scripts/train-model.mjs 실제자료.json models --count 60 --hidden 32,16,8 --availability opening-plus-7d
node --test tests/domain.test.mjs
```

`test-artifacts/synthetic-model.json`은 **합성 시험자료로 실제 학습한 시험용 모델**입니다. 운영 API는 이 모델을 거절합니다. 이 모델의 수치는 실제 공사 예측 성적으로 사용할 수 없습니다.

## 나라장터 자료 연결

정상 공개 UI를 통한 배치 수집·정규화 결과를 사이트에 반영했습니다. 매일 갱신 실행 절차와 자료 범위는 DAILY-SYNC.md에 있습니다. 공개 웹 화면을 통한 자료 조회에는 API 신청이 필요하지 않습니다. 공식 API 방식으로 자동화할 때만 아래 서비스의 활용신청과 인증키가 필요합니다.

- 공고: https://www.data.go.kr/data/15129394/openapi.do
- 개찰: https://www.data.go.kr/data/15129397/openapi.do

`scripts/collect-g2b.mjs`는 현재 공식 Swagger 경로·DOCX 파라미터에 맞춘 **원본 수집 준비 코드**입니다. 인증키가 없어 정상 API 응답 검증은 하지 못했습니다. 일반 인증키(Decoding)를 `G2B_SERVICE_KEY` 환경변수로 주입하고 실행합니다. 소스·명령 인수·공유 파일에 인증키를 적지 마세요.

```powershell
node scripts/collect-g2b.mjs --service notices --from 202610010000 --to 202610012359
node scripts/collect-g2b.mjs --service prices --notice R26BK01491586
node scripts/collect-g2b.mjs --service participants --notice R26BK01491586 --round 000 --class 0 --rebid 000
```

각 API의 원본 응답·수집시점을 저장합니다. 서비스별 실제 응답을 확인한 뒤 공고조건을 검토하고 `bid-compass/1.0`으로 변환해야 합니다. A값 항목 적용 여부, 업체 배제 사유와 예가 평균 반올림을 검산합니다. 공식 공개시각은 추정값으로 덮어쓰지 않으며, 연구용 이용시점 가정은 별도 메타데이터로 처리합니다. 예가의 재입찰 필드는 Swagger `rbidNtceNo`, DOCX `rbidNo`로 달라 원본 확인이 필요합니다.

## API 계약

요청은 기존 로그인 계정 또는 브라우저 쿠키로 구분됩니다. 첫 GET 요청에서 브라우저 쿠키를 발급합니다. 모든 쓰기는 동일 출처 Origin과 JSON 요청이 필요하며, 비로그인 쓰기는 발급된 쿠키가 있어야 합니다. 공개 자료를 제외한 공고·모델·예측·저장 기록·백업은 해당 계정 또는 브라우저 범위에서만 조회됩니다.

- `POST /api/predict`: `{noticeId, region, assumedPriceRank, mode, modelVersion?}`. 예측 ID, 모델 버전/지문, 학습 종료일, 분석 기준일, 번호 조건, 두 후보의 ID·5자리 비율·구간·설명·금액을 반환합니다.
- `POST /api/save`: `{predictionId, candidateId, revisionOf?}`. 서버에 저장된 예측만 선택 가능하며 사용자 ID·모델·입력·금액을 함께 보존합니다.
- `GET /api/record?id=...`: 당시 선택, 최신 개찰 결과 비교, 가격순↔원본번호, 수정 이력.
- `POST /api/import`: `{schemaVersion:'bid-compass/1.0',notices:[...]}`. 행별 검산 및 제외 사유 저장.
- `GET /api/notice?id=...`: 공고별 전체 개찰자료.
- `GET /api/collection`: 수집자료 및 제외사유 백업.
- `GET /api/training-plan?trainingCount=60&availabilityPolicy=opening-plus-7d`: 학습 가능 여부, 실제 확보 건수와 분할 구간.
- `POST /api/train`: `{trainingCount:60, annHiddenLayers:[32,16,8], availabilityPolicy:'opening-plus-7d'}`. 지정한 수로 학습하고 새 모델 버전 생성.
- `GET /api/model?version=...`, `GET /api/export`: 본인의 모델·자료 백업.

예측 캐시는 사용하지 않습니다. 모델 오류·자료 부족·공식 조회 미연결은 오류 코드로 반환하며 임의 추천값으로 대체하지 않습니다.

## 로컬 실행과 검증

Node 22.13 이상, npm, Git이 필요합니다. `npm ci`, `npm run db:generate`, Sites 빌드 후 README 스타터 명령에 따라 로컬 D1 마이그레이션을 적용하고 `npm run dev`로 시작합니다. 개발 로그인은 로컬 전용 시험 계정입니다.

`tests/domain.test.mjs`는 공식 공고 산식, 조합 수, 미래 정보 차단, 순위·동가·하한·순공사원가, 이력·사용자 분리를 확인합니다. `tests/browser-empty.mjs`는 자료 부족·조회 실패와 모바일 레이아웃을 확인합니다.

`tests/availability.test.mjs`는 공개시각 원본 보존·연구 가정 분리·학습과 추론 기준 일치를 확인합니다. `tests/browser-real-flow.mjs`는 실제 공고로 학습→예측→저장→개찰비교→재열람을, `tests/browser-live-flow.mjs`는 실제 미개찰 공고의 사전 저장·결과 대기를 확인합니다.

`tests/training-window.test.mjs`는 30·60·200건의 정확한 학습 표본 수, 동일한 검증 구간, 시간순 제외 조건을 확인합니다.

`tests/browser-flow.mjs`는 로컬 전용 `BID_COMPASS_TEST_MODE=local-fixtures`에서 합성자료로 입력→학습→예측→저장→결과등록→재열람을 확인합니다. 이 플래그는 루프백 호스트에서만 유효하며 운영 환경에 배포하지 않습니다. 브라우저 시험에는 Playwright와 Edge가 필요합니다.

제한: 운영 공고 최대 600건, 한번 가져오기 100건/3MB, 표시 기록 5,000행 제한입니다. 대규모 자료·학습은 별도 배치 처리와 페이지네이션 확장이 필요합니다. 소수 금액 단가계약, 모든 공고별 특수 가격규칙, 실제 계약 여부 판정은 지원하지 않습니다. 배치 수집기의 원문을 scripts/build-public-dataset.mjs로 정규화하고 scripts/train-public-models.mjs로 기본 모델을 재학습합니다.

## ANN 구조 확장

`scripts/train-ann-architectures.mjs`는 기존 1층 모델 3개를 보존하고 2·3층을 각각 30·60·200건으로 학습해 추가합니다. 기존 모델과 학습/모델 선택/최종 검증 공고 ID가 같은지 검사합니다. 층 구성은 모델 파일, 검증 성적, 예측 및 저장 기록에 보존됩니다. `tests/dense-ann.test.mjs`는 비선형 표본 학습, JSON 저장/복구, 손상된 가중치 거절, 기존 1층 추론 보존과 동일 검증 구간을 확인합니다. 브라우저 검증은 `BID_COMPASS_TEST_ANN=32-16` 또는 `32-16-8`로 구성을 선택합니다.

웹의 2·3층 ANN 학습은 5 epoch씩 서버에 진행 상태를 저장하고 다음 요청에서 이어갑니다. 전체 60 epoch와 학습 공고 수는 동일하며, 요청 분할 전후의 최종 가중치·검증 결과가 정확히 같은지 시험합니다. POST /api/train의 202 응답은 jobId·completedEpochs·totalEpochs를 반환하며 같은 경로에 {jobId}를 보내면 계속 진행합니다. 완료되면 200 응답으로 모델을 반환합니다. 진행 상태는 방문자별로 격리되며 24시간 이내 이어갈 수 있습니다. 학습 도중 창을 열어 두어야 합니다.
